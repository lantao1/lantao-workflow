# Workflow Quick Reference

**Model:** Contractor (you direct, Claude orchestrates)

---

## The Loop

```
Your instruction
    ↓
[PLAN] (if multi-file or unclear) → Show plan → Your approval
    ↓
[EXECUTE] Implement, verify, done
    ↓
[REPORT] Summary + what's ready
    ↓
Repeat
```

---

## I Ask You When

- **Design forks:** "Option A (fast) vs. Option B (robust). Which?"
- **Code ambiguity:** "Spec unclear on X. Assume Y?"
- **Replication edge case:** "Just missed tolerance. Investigate?"
- **Scope question:** "Also refactor Y while here, or focus on X?"
- **Any change to the text:** old and new side by side first; nothing lands before you approve
- **New content:** a repair that needs a new fact, claim, number or citation is flagged for you
- **Commit:** only when you say so

---

## I Just Execute When

- Code fix is obvious (bug, pattern application)
- Verification (tolerance checks, tests, compilation)
- Documentation (session logs, landing records, tracker rows)
- Plotting (per established standards)
- Deployment (after you approve, I ship automatically)

## Non-Negotiables (Customize These)

<!-- Lantao's defaults for every project. Add the project's own items below them. -->

- **Paths:** relative only. Every path comes from one driver or setup file; a stage run without
  its driver stops with an error. A gate resolves paths from its own folder, never an absolute path.
- **Seeds:** every bootstrap or simulation call carries its own seed, and every estimating script
  sets the sort seed too, so a rerun is byte-identical and does not depend on execution order.
- **Numbers:** every number in the text comes from an output file and is bound by a gate. Nothing
  is typed by hand; a printed value without a live generator is unverified.
- **Tolerance:** a printed number equals its output at the printed precision. A significance star
  near a threshold is rechecked with more draws under two seeds before it is printed. For numbers
  printed in the text the printed-precision rule governs; the tolerance table in
  `.claude/rules/replication-protocol.md` applies only to replicating another paper's numbers.
- **Figures:** generated by script and looked at on the rendered page at print size; every point
  the text names carries a checked label.
- **Source of truth:** the scripts and the `.tex`. Word copies come from `scripts/tools/tex2docx.py`
  and are never edited by hand.
- **Approval:** nothing lands in a live document before the author approves old and new side by side.
- **Commits:** never unless the author asks.
- **Language:** chat in Chinese; everything that is or becomes deliverable content in English.
  Round records (intake, proposal, landing) may carry Chinese commentary, with quoted and proposed
  sentences verbatim.
- **Color palette (slides only; delete this line if the project has no slides):** [per project];
  keep `Preambles/header.tex` and `Quarto/theme-template.scss` in step
  (`./scripts/check-palette-sync.sh`).

## Preferences

<!-- Lantao's defaults. Adjust per project as the working style settles. -->

**Visual:** figures from scripts only; a translated document gets its own figure files
(`<name>_<lang>.png`) and the originals are confirmed unchanged.
**Reporting:** short and direct. Answers first, one line each; then one numbered action list; then
at most two yes/no questions. Old/new pairs, sweeps and evidence go in the plan or proposal file, linked.
**Session logs:** Always (post-plan, incremental, end-of-session)
**Replication:** strict. A new switch is proved inert first (switched off, it rebuilds the previous
outputs byte for byte); one driver per output family; diagnostic reruns write to scratch, never to
the published outputs. Near-misses (a star close to its threshold, a value barely outside
tolerance) go to the author.

## Exploration Mode

For experimental work, use the **Fast-Track** workflow:
- Work in `explorations/` folder
- 60/100 quality threshold (vs. 80/100 for production)
- No plan needed — just a research value check (2 min)
- See `.claude/rules/exploration-fast-track.md`
